# Instructions for Codex

## Project rules
- Read and understand existing code before suggesting changes.
- Never modify files unless explicitly requested.
- Do not refactor unrelated code.
- Do not invent functions, classes, or APIs.
- Prefer minimal changes.
- Prefer simple syntax to a newer and more complicated one.

## Python rules
- Follow existing project conventions.
- Preserve existing function signatures.
- Do not introduce unnecessary dependencies.
- Check existing tests before proposing fixes.

## Communication
- Explain the root cause before suggesting a fix.
- If uncertain, say so instead of guessing.
- Do not claim tests passed unless they were executed.
